# v7.0: Nothing Ships Unverified

> The first version whose contract is about what LEAVES the brain, not what lives inside it.

## The problem (verified)

Every major so far hardened the inside: v4 made an unwired rule a corruption, v6 made every fail-closed gate prove it blocks. Neither says anything about the moment that actually costs money: the send. On 2026-09-05 a formal complaint email left the brain asserting that a bank charge "did not correspond to any contracted service". The charge was a purchase the operator had itemized to that same counterpart in chat weeks earlier, and the brain memory held it too. Nobody looked. A correction followed minutes later, and a correction inside a money claim discredits the claims that were right. The gate that now catches that phrase (`COMMS.unsourced-absence`, #257) was written after the fact, which is how every COMMS gate in this brain was born: one incident, one phrase, one Stop hook.

That is the pattern, not the exception. Measured at v6.24.0 with `brain_doctor.py`:

| Surface | Reading | What it means |
|---|---|---|
| Enforcement floor | FORCED 25/31 gateable (81%) | 6 gate-shaped rules run at model discretion under a waiver |
| Detect tier | 14 rules | They report; nothing is stopped |
| Waivers | 6, expiry-tracked | `CODE.dry-run-first`, `FLOW.delegate-gate`, `FLOW.3d-diligent-gate`, `FLOW.enforcement-scripts`, `COMMS.no-pause`, `FLOW.budget-halt` |
| Memory directives | 128/128 REFLEX, "obedience unproven" | Every lesson the brain has learned is injected as text and enforced by nothing |
| Outward-send gates | 6 Stop hooks, each keyed on one phrase class | Post hoc, per incident, blind to the send they did not anticipate |

The honest statement of v6 is: a rule that exists is proven to bite. The honest statement of what v6 does not give is: a send can still leave with zero receipts, as long as no known phrase trips a known gate.

"Code without defects" is not a contract a brain can sign; no gate proves the absence of an unknown class. "Nothing ships unverified" is: every outward action carries machine receipts, and a send without them is impossible, not discouraged.

## The contract

An **outward action** is any tool call whose effect leaves the operator's machine and cannot be recalled: sending mail, sending a chat message, merging a PR, deploying, publishing an artifact, writing to a client system.

An outward action is allowed only when the turn carries a **receipt bundle**:

1. **Seek receipt.** For every claim of fact about the counterpart or the past (an amount, a date, an absence, a category), a lookup ran in this turn: memory seek, chat search, mail search, or the arm expediente. The receipt is the act of looking, never its result. A lookup that returns message bodies counts (messages, mail); a chat listing or a last-interaction stamp does not, because it cannot refute anything.
2. **QA receipt.** For the merge of a PR, an independent verdict on the judgment tier, recorded by the harness, not asserted in prose. This one is enforced by `scripts/qa-merge-gate.py` at Bash PreToolUse on the merge command, not by the send gate. Since `docs/specs/202610012100-qa-receipt-bound-to-head/` the verdict is bound to the commit it reviewed: the reviewer ends with `QA-VERDICT`, `QA-SCOPE: PR #<n>` and `QA-HEAD: <40-digit commit>`, the receipt is anchored to the harness `uuid` of that transcript entry, and the merge must be a direct one pinned to that commit (`gh pr merge <n> --match-head-commit <sha>`, or REST `-f sha=<sha>`), so a commit pushed after the review cannot ride on its PASS. The newest receipt for the PR and the commit decides, by its entry's harness timestamp, so a later NEEDS-WORK revokes an earlier PASS, and one with no valid `QA-HEAD` revokes every commit of the PR. Every publish sub-command joined by `;`, `&&`, `||`, `|`, `|&`, `&` or a newline is decided on its own; while an approval is exported, a command that mentions a merge inside syntax the gate does not parse (a backslash, a heredoc, `$'...'`, a substitution, `sh -c`, `eval`) is blocked whole, and so is a sub-command that names a merge the gate cannot identify as one. Redirections are removed before the pin is read, and the pin must occur exactly once in the command, so a misreading of gh's flag grammar can only lose it, never swap in another commit. Every command is read by a bash-shaped reader and by the previous reader, and a publish either finds is decided, so neither gate is weaker than before; the target repo is judged under both readings and the approved PR number is never ruled out of scope, and a seek receipt counts only when both readings find it. An approved merge carrying a `$`, braces or a glob is blocked too, because its pin can expand into another commit. Residual: without an approval a merge hidden by shell indirection, and with one a merge reached through a variable, function or alias that names the command; the exported approval is the boundary. Residual: a later PASS from a different reviewer overrides an earlier NEEDS-WORK, and both stay in the ledger.
3. **Gate receipt.** Every fail-closed gate that watches this class of action has a green `--selftest` at HEAD, and no waiver covers it.
4. **Ask receipt.** The operator's own prompt for the turn asks to send, with a non-negated send verb outside quotes (standing directive 2026-08-14: deliver by default, transmit per message on request). `send-ok` is the hatch.

A send is denied at PreToolUse when the seek, gate or ask receipt is missing, with the missing receipt named. A merge of a PR is denied when the QA receipt is missing, by its own gate. `absence-ok`-style hatches stay per line, never per turn.

## The architecture

Four load-bearing pieces, in dependency order.

1. **One send choke point.** A single PreToolUse gate (`g__pretool-mcp__outward-send.py`) matches every outward tool by name (mail, WhatsApp bridges, `gh pr merge`, deploy CLIs, artifact publish) and reads the turn's receipt ledger. The six Stop-time COMMS gates keep their phrase logic but become *contributors* to the ledger, not independent tripwires: each one writes what it checked, and the choke point refuses when the ledger is empty for a class the send needs. Today the checks fire after the reply is composed and only on the phrase they know; after this they fire before the tool runs and on the absence of evidence.

2. **The receipt ledger.** A per-session file (`~/.claude/.cache/receipts/<session>.jsonl`, gitignored, same discipline as goal-anchor) appended by hooks, never by prose: PostToolUse on seek tools writes a seek receipt; the QA subagent's verdict is written by the harness, not pasted by the model; `--selftest` runs write gate receipts. The model never writes a receipt through a hook, which is what makes the ledger worth reading. It does not make a receipt unforgeable: a forged entry has to carry the harness fields, sit in the session's own directory, and survive the consumer re-verifying it against the transcript, and it stays visible to anyone who audits. The agent-proof boundary is still `OCTO_MERGE_APPROVE`: only the harness environment authorizes.

3. **Floor 100%, no grey zone.** The 6 waivers get a decision each: promote to fail-closed with a fixture pair, or demote to PRESENCE and say so in the anchor. The 14 detect-tier rules get the same binary. `brain_doctor` grows one assertion: `gateable && !fail-closed` with no waiver is already a FAIL; v7 removes the waiver escape for rules older than 90 days.

4. **No incident closes without a fixture.** Each incident recorded in memory that names a gate as its mechanism must have a `registry/fixtures/<rule-id>/` pair where the benign fixture is the violation minus one edit (the derivation rule already in memory). The doctor's `corpus-coverage` gains a column: incidents with mechanism / incidents with fixture. The 128 REFLEX directives are triaged by recurrence: any lesson with two or more memories of the same class becomes a gate candidate, and the candidate list prints in the doctor until it is empty or explicitly demoted.

## Release criterion

v7.0.0 ships when `brain_doctor.py` prints all of:

- Floor: FORCED n/n gateable (100%), waived 0.
- Outward-send gate: fixture-proven, covering every send tool registered in `hooks.json`.
- Incident-fixture coverage: 100% of incidents that name a mechanism.
- REFLEX triage: 0 recurrent lessons without a decision.

Not a claim of zero defects. A claim that zero known defect classes are unwired, and that no send leaves without receipts. The next unknown class will still get through once; v7 guarantees it gets through with a ledger that shows exactly which receipt was missing, and that the gate written for it is proven before the incident closes.

## The receipts in detail (moved from CLAUDE.md)

These paragraphs were the constitution's own text until v10 (T13), moved here so `CLAUDE.md` keeps only what every session needs. They are kept as written, with em-dashes normalised; `CLAUDE.md` now carries a short paragraph pointing here.

The contract of v7 (`docs/architecture/v7-nothing-ships-unverified.md`): an outward action leaves only with machine receipts, and a receipt is something a HOOK wrote in the harness process and a consumer re-verified against something the model does not own. Four receipts, four mechanisms, plus the trail of what left:
- **Receipt ledger** (`scripts/receipt_ledger.py`, gitignored `~/.claude/.cache/receipts/`): `scripts/r__posttool__receipt-seek.py` records every chat, mail or memory lookup with its harness-supplied `tool_use_id`; a consumer accepts the receipt only if that id is a real tool_use in the current turn of the transcript, so a hand-typed line names nothing. `brain_doctor` records a gate receipt (the git tree hash of `scripts/`, `registry/` and `hooks.json`; HEAD is recorded, not required, so a squash-merge with the same gate tree keeps it valid) when gate-liveness passes on a clean tree, where clean also means no `assume-unchanged` or `skip-worktree` flags and every tracked gate file's blob equal to HEAD; `.githooks/pre-push` runs `brain_doctor --gate-receipt` so a push and a receipt are one event, and an uncommitted edit under the gate surfaces voids the receipt.
- **Outward-send gate** (`scripts/g__pretool-mcp__outward-send.py`, PreToolUse on mail send/reply/forward, WhatsApp send, and Bash when it invokes the support bridge, a deploy or a release): denies the send when the brain's HEAD has no gate receipt, when the body carries an absence claim and the turn has no anchored seek receipt, or when the body carries an unsourced attribute in a consent context or a first-person promise; a mail send whose subject opens with Re:/Fwd: and carries no threadId/inReplyTo is denied too (a reply outside its thread cuts the sequence). It imports the exact detectors of the Stop gates, so those six are contributors, not rivals; drafts stay with them, sends come here. Hatches (`absence-ok`, `attribute-ok`, `draft-promise-ok`, `send-ok`) count only in the operator's own prompt for the turn, never inside the body: a token in the body would ship to the recipient and be self-serve. A seek receipt counts only when the tool_use it names is itself a seek (a seek tool, or a Bash sub-command invoking one at a command boundary). It also denies a send when the operator's own prompt for the turn carries no explicit, non-negated send request (standing directive 2026-08-14: deliver paste-ready by default, transmit only the message that was asked for). A send request is a verb from the tracked `registry/send-ask.yaml` list (Spanish and English, matched without regard to case or accents) or the original matcher; a bare go-ahead such as `dale` never counts. Only an operator entry opens a turn with words that count (hatches included). When a task notification, a peer message or a compact summary opened the turn, the request is read from the operator's latest real prompt, and it counts only if this send's panel receipt was recorded after that prompt. A Bash command that names the support script anywhere is a send unless the whole command is one plain read (`panel_digest.plain_read`: one `cat`, `head`, `tail`, `grep`, `wc`, `stat`, `file`, `diff`, `ls`, `chmod` or `chown` with plain words, a plain `sed -n <range> <script>`, or `<script> --help`, with no pipe, chain, newline, redirect, substitution or `-c` body). There is no list of executors, because that list never converged. The cost is that a pipe, a chain or a git or editor command naming the script is judged as a send, so read the script with one plain command and no pipe. `send-ok` is the hatch, and so is a recipient listed in the private `company/config/outward-send-autonomous.json` (a chat where the operator gave standing instructions to answer and act; that waiver covers the send ask only, every other check still runs, and the JID never enters this repo); a listed chat marked `send_ok_from_chat` also lets the operator type `send-ok` in the chat itself, from his own phone (`is_from_me` in the personal bridge store, fixed path, no per-chat override), to release a MESSAGE send to a third party inside that chat's window (default 60 min, valid 1..240, anything else disables the hatch); a deploy or a release is never released by a chat token. Every MESSAGE send also needs a panel receipt (below), and nothing waives that one: `send-ok`, the autonomous-chat allowlist and a chat-typed `send-ok` lift only the send ask. Residual, stated in the gate header: the store and the config are files under `$HOME` a hooked process can write, so one config write plus one store row lifts the send ask for every message send to any recipient for up to 240 minutes, wider than the per-recipient allowlist and visible in the bridge database and the kernel journal.
- **Panel receipt** (operator directive 2026-10-02: no message leaves without a panel, however small it looks). `scripts/panel_digest.py` hashes what a send carries: the text (subject, body, htmlBody, forwardText, message) normalized for whitespace, the sha256 of every attachment's bytes, and the recipients, plus the people a support-bridge send mentions (`--menciones`, printed as `PANEL-MENTION` lines; the key is added only when someone is mentioned, so every other digest is unchanged). The support script's arguments have ONE reader, `panel_digest.parse_bridge_args`, shared by the digest, the gate's recipient readers and the sent-message ledger: the script strips its value flags wherever they sit, and a reader that does not know a flag takes its value for the recipient or the flag for message text. A test compares the script's own flag arms with the reader's list, so a flag added to one and not the other fails. Bash, shlex and Python disagree on what splits a word and what expands in it (braces, globs, a tilde after `=`, a `#` in mid-word, a carriage return, a no-break space), so the line is read through an allowlist: outside quotes only ASCII letters, digits and `@._,:/+%-=`, a space or tab between words and a backslash before a printable character pass, a `~` only as `~` or `~/...` at the start of the script's path or the `--archivo` path (bash also expands `~+`, `~-`, `~N`, `~user`), no control character even inside quotes, and the scanner's words must equal shlex's tokens. Anything else denies, and the remedy is to quote the message. Each send tool has a known key set and any other key denies (a snake_case `draft_id` or `html_body` included); a draft sent by id denies. A stated digest binds to nothing, so the reviewer's final report must carry the panel block that `panel_digest.py --tool-input <json> --tool-name <tool> --panel-request` prints (`PANEL-TO`, `PANEL-ATTACH`, the exact text between `PANEL-BODY-BEGIN` and `PANEL-BODY-END`), then `PANEL-VERDICT: PASS|NEEDS-WORK` and `PANEL-SHA256`; the SubagentStop reflex records a `panel` receipt only when the digest recomputed from that block equals the stated one, and the consumer recomputes it again from the re-read entry. The outward-send gate denies every mail send, reply and forward (both Gmail servers), every WhatsApp `send_message`/`send_file`/`send_audio_message` and every support-bridge call (`--archivo` and `--menciones` included) unless the newest panel receipt for that exact digest, from a reviewer persona, in this session and inside 120 minutes, says PASS and has not been spent: a receipt authorises ONE send, read off the sent-message ledger. A later NEEDS-WORK revokes; an edited body, recipient, mention or attachment is a new digest. There is no hatch, in the prompt or in the body. It fails closed: an unreadable attachment, a bridge call that is not the only command of its line (no chaining, pipe, redirection, newline, `$`, backtick or heredoc) or two shell readings that disagree all deny, and a Bash command that reaches a bridge's send path without the script or the MCP tool (`/api/send`, `/api/react`, a bridge port, an `ssm send-command` with a bridge payload) is denied outright. Deploys and releases are not messages and stay out of scope. The raw-send rules read the command raw, after quote removal, with split literals joined, after percent-decoding until stable and with `/api/` paths normalized: any request to a bridge port (leading zeros included) on ANY host, or to a URL whose host or port holds a `$`, whose path is not a read route both bridges expose (`/api/revoke`, the recall path, `/api/download`, `/api/group-participants`, checked in their `main.go`; `/api/status` is not one), whatever the method, and any request naming `/api/send` or `/api/react`; an `ssm send-command` that mentions a bridge on any instance (base64 blobs in the payload are decoded and checked too), or, when its target hosts a bridge per the private `company/config/wa-puentes.json` (a missing config, `--targets` or an unreadable instance id count as bridge-hosting), carries anything beyond an allowlist: plain reads (not `sort`, `uniq` or `date`, which write without redirection), the operator-approved deploy that only writes decoded, inspected files under `/opt/<dir>/` (plus chmod, chown, mkdir -p, mv, cp there; standard and url-safe blobs, split fragments joined, an undecodable candidate denies), and `systemctl daemon-reload`; inline interpreter code that names a bridge port off the read routes, or carries an HTTP or socket primitive with a bridge-shaped target and a write shape, or with an `api/` path and a local host hint; and an HTTP client whose URL is built at run time. Residuals, stated in the spec: a forward hashes its comment only; browser sends (claude-in-chrome) and calendar invitations are not on the matcher; a script written in one call and run in another, or a command hidden behind an alias, function or symlink, is not seen; parallel tool calls can race single use (both pass PreToolUse before either PostToolUse); `sent.jsonl` is deletable by a hooked process; a reviewer can repeat PANEL-ATTACH hashes without opening the file; the bridge-hosting set is a private file a hooked process can edit; a non-reader command that only mentions a bridge request (`echo '... :8081/x' >> notes.md`) is denied; a file a deploy writes under `/opt` can be run later by an existing timer or unit, a symlink under `/opt` cannot be resolved from here, and blobs are decoded one layer deep (all three accepted by the operator on 2026-10-03, reduced by decoding the blob, not removed); a target computed inside inline code with no `api/` text is not seen; and the rules deny 117 of 6,112 replayed real commands, most of them intended or fail-closed on an unreadable target. Deferred: structural control (the bridge reachable only through a socket or user the gated path owns), because five QA rounds showed text deny-lists do not converge. Rule `FLOW.panel-before-send`, fixtures `registry/fixtures/FLOW.panel-before-send/`; the existing outward-send fixtures carry a seeded PASS (`scripts/panel_fixture_seed.py --reset`) so each still proves its own check.
- **Sent-message ledger** (`scripts/r__posttool__sent-ledger.py`, PostToolUse on the same send tools): every message that left gets a line in the gitignored `~/.claude/.cache/receipts/sent.jsonl` with its channel (gmail, wa-personal, wa-support), recipient, the message id the tool returned, its digest, the panel receipt that decided it, the session and the time. - **QA receipt** (`scripts/r__subagent-stop__qa-receipt.py`, SubagentStop): a QA subagent that ends with `QA-VERDICT: PASS|FAIL|NEEDS-WORK`, `QA-SCOPE: PR #<n>` and `QA-HEAD: <40-digit commit>` gets its verdict recorded with the harness-written agent transcript path and the harness `uuid` and `timestamp` of the entry it came from. A PASS approves the COMMIT it reviewed, not the PR: `qa-merge-gate` requires, on top of the operator's `OCTO_MERGE_APPROVE`, a direct merge pinned to that commit (`gh pr merge <n> --match-head-commit <sha>`, or REST `-f sha=<sha>`; GitHub refuses a head that differs, and `--auto` is refused because its re-check is not established), and decides on the NEWEST receipt for that PR and that commit, ordered by its entry's harness timestamp across sessions, so a later NEEDS-WORK revokes an earlier PASS, and one with no valid `QA-HEAD` revokes every commit of the PR. Every publish sub-command joined by `;`, `&&`, `||`, `|`, `|&`, `&` or a newline is decided, and a pin inside a bash comment is no pin. While an approval is exported, a command that mentions a merge inside syntax the gate does not parse (a backslash, a heredoc, `$'...'`, a substitution, `sh -c`, `eval`) is blocked whole, and so is any part of a command that names a merge the gate cannot identify as one (a wrapper such as `sudo` or `xargs` in front of gh), so the approved path reads only plain commands. Every command is read twice, by a bash-shaped reader and by the gate's previous reader, and a publish either one finds is decided, so neither this gate nor the outward-send gate that shares the splitter is weaker than before (replayed: 0 of 20,997 real commands lost a detection); ### Unsourced-attribute (a circumstance does not license the category)
