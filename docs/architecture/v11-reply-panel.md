# v11 reply panel

Spec: `docs/specs/202610141340-v11-reply-panel/` (FR-01 to FR-05, AC-01 to AC-17). This page is the source the registry row `FLOW.panel-before-reply` points at from its CLAUDE.md anchor "Reply panel".

v7 made an unverified send to a third party impossible: no message leaves without a PASS panel receipt for its exact digest (`FLOW.panel-before-send`). v11 moves that floor to the operator. Every reply the main loop gives him carries a PASS panel receipt for its exact text, recorded by a hook from an independent reviewer, or the turn is sent back.

## Why Stop, and not before display

Claude Code has no hook that can stop text before it is displayed: "MessageDisplay hooks have no decision control. They can't block the message" (code.claude.com/docs/en/hooks). MessageDisplay can replace a streamed delta on screen, but it runs per streamed batch, before the whole reply and its digest exist. So the gate runs at Stop, after the reply was shown. The protocol keeps an unreviewed reply off the screen: draft the reply, have a reviewer read it, then emit exactly the reviewed text. The gate makes skipping the protocol cost a rewrite turn, every time.

## The protocol

1. Write the reply to a file and run `python3 ~/.claude/scripts/panel_digest.py --panel-request --to operator --body-file <file>`. It first runs the preflight (`scripts/panel_preflight.py`): every other Stop hook that judges reply text runs on the draft, appended to a copy of the session transcript, and when one would block, no block is printed and the command exits 1, so the text the reviewers read is the text that ends the turn. It then prints the source class and quorum on stderr and the reviewer block (`PANEL-TO: operator`, `PANEL-BODY-BEGIN` ... `PANEL-BODY-END`, `PANEL-SHA256`) on stdout. `--preflight` runs only the check; `--no-preflight` skips it.
2. Launch reviewer subagents with that block: three for a SELF reply, one for a SOURCED reply (see the quorum below). Its agent type must match `receipt_ledger.PANEL_AGENT_TYPE` (`qa|review|reality|evidence|checker|verif|audit|panel`: Reality Checker, Code Reviewer, Evidence Collector). general-purpose, claude and fork do not match. The reviewer repeats the block and ends with `PANEL-VERDICT: PASS | NEEDS-WORK` and `PANEL-SHA256`.
3. `r__subagent-stop__qa-receipt.py` records a `panel` receipt only when the reviewer's own report carries the block and it recomputes to the stated digest. No new receipt machinery: a recipient is free text in `PANEL-TO`.
4. Emit exactly the reviewed text as the final reply.

Reviewers run in the background in this harness, so the main loop can end a turn while it waits. That waiting stop is a status line of at most 30 words, and the gate lets it through while a subagent launched or messaged in this operator turn still runs, at most 3 times per operator prompt.

## The gate

`scripts/g__stop__reply-panel.py`, on Stop, timeout 20 seconds. It reads the Stop payload (`last_assistant_message`, `stop_hook_active`, `transcript_path`, `session_id`). The digest is `panel_digest.digest(last_assistant_message, recipients=["operator"])`: whitespace layout does not change it, one changed word does.

It exits 0 when the first of these holds, in this order:

| # | Condition |
|---|---|
| 1 | `OCTO_REPLY_PANEL=off` in the hook's own environment. Read before any import that can fail. |
| 2 | `last_assistant_message` is an empty or whitespace string. An absent key is not empty: the gate cannot decide and exits 2 ("payload has no last_assistant_message"). |
| 3 | The operator's own prompt for the turn carries the word `panel-skip`. |
| 4 | The reply is a status line (at most 30 whitespace-split words, no claim marker), a subagent launched or messaged after the operator prompt is still running, and fewer than 3 status stops were already exempted for this prompt. |
| 5 | The deciding receipt for the digest in this session (`receipt_ledger.panel_receipts_for`, first entry) is a PASS with `verdict_ts` strictly newer than the operator's prompt, and PASS receipts newer than the prompt come from at least the quorum of distinct reviewer agent ids: 3 for a SELF reply, 1 for a SOURCED reply. |

Otherwise it exits 2. Its stderr names the digest, the panel-request command and the accepted reviewer types, and never the skip word, so its own feedback cannot read as a waiver. `stop_hook_active` changes nothing: there is no block-once.

**The operator's prompt.** The gate walks the transcript backwards with the send gate's `_prompt_entries_reversed`, `_origin`, `_is_operator_opener` and `_entry_text`, loaded by file name. It passes over tool results, task notifications, peer messages and hand-backs, sidechain entries and every `isMeta` entry (Stop-hook feedback lands as a user entry with `isMeta: true`). The first entry whose `origin.kind` is `human`, or that has no origin, is the prompt; if that entry is not harness-written (`_is_operator_opener` fails), there is no prompt and the gate exits 2. An entry with any other origin kind also ends the walk with no prompt, as the send gate's `turn_read` does. A compact summary (`isCompactSummary: true`) reached before any human entry means a context continuation opened the turn (AC-22): it carries no operator words, so the anchor is the summary itself, with empty text and its own timestamp as the newer-than bound. A receipt must then be newer than the summary. A summary the harness did not write (no uuid or timestamp) ends the walk with no prompt. A helper missing from the send gate is an error that names it.

**The quorum scales with the source (FR-06).** Operator directive 2026-10-14: a reply whose basis is SELF is treated as a likely hallucination and needs a panel of three. Every line of the reply that starts with `Provenance:`, `Procedencia:` or `Herkunft:` is a provenance line (leading blanks, a `>` and markdown emphasis around the label are tolerated). The reply is SELF when it has none, or when ANY of them has no `Basis` field, an empty Basis, a Basis that is only (ignoring case, surrounding blanks and trailing punctuation) `none`, `nothing`, `n/a`, `na` or a run of hyphens, en dashes or em dashes, or a Basis that names self as its source. The field is the word `Basis` in any case followed by a colon or by whitespace (`Basis: /path` and `Basis /path` are the same field), and the label may be followed by a colon or by a `·` separator (`Procedencia · Basis: ...`). A Basis names self when it carries `self`, `own reasoning`, `razonamiento propio`, `eigene Überlegung` or `eigene Ueberlegung` as a standalone word (case-insensitive); when a token outside backticks starts with `self` and is not a path or file name (`self-review`, `self-assessment`, a bare `selftest`; a token with a `/` or a file extension, or a backticked span, is a path); or when one of its items (split on `,` `;` `+` `&` and/y/und) is nothing but a self source (`myself`, `self-evident`, `my own reasoning`, `reasoning`). So `scripts/selftest.py`, `selftest.py`, `` `self-review.md` `` and `git log, checked myself` are SOURCED; `self-review`, `self-review of scripts/x.py` and `myself` alone are SELF. A SOURCED line written after a SELF one (in a code block or not) does not lift it: over-reading costs two more reviewers, never a weaker check. Otherwise the reply is SOURCED. Distinct means distinct agent ids: one reviewer recorded three times is one reviewer. `receipt_ledger.panel_receipts_for` holds the per-receipt validation and returns every validated receipt, deciding first (a PASS whose anchor check raises counts as not standing); `panel_latest_for` returns its first entry, so `panel_pass_for` and the send gate are unchanged. The stderr names the source class and the count ("it has 1 of 3"). The status-line exemption for a pending reviewer is the same for both classes.

**Input-needed replies (quorum 1).** A reply whose only job is to ask the operator for a fact he alone holds is classed INPUT, with the SOURCED quorum of one. Outside its footer (at most one provenance line, after the question) the reply is exactly one line starting `input-needed:` that names the unknown and ends with the reply's only `?`, plus at most one context line before it of at most 15 words. Neither line carries a claim marker (`status_claim`), and the question is not a menu, a permission or direction ask, or an irreducible operator step such as a payment, a login or a send-ok (read with the no-menu gate's own `is_choice_question` and `_irreducible_object`; an error loading that gate keeps the normal class). A footer whose Basis is empty or names self wins: the reply stays SELF. The reviewer's job for such a reply is to confirm the fact is not available from context; it never skips the panel. The 15-word context line and the marker check are a speed bump, not a boundary: a short assertion without a marker can ride in the context line, and the one reviewer is the check on it. The no-menu gate reads past the `input-needed:` label, so the label cannot hide a menu from it.

**A receipt is not spent.** It is bound to one exact text and one operator turn. A receipt from an earlier turn never covers this one, and a NEEDS-WORK newer than the PASS revokes it (the ledger's own rule). Repeating the identical text in the same turn is the same reply.

**Status line while a subagent runs.** The boundary is structural: a subagent launched or messaged after the operator's prompt, still running, and at most `STATUS_STOPS_MAX` (3) exempted status stops per operator prompt; the fourth stop needs a reviewed reply. A subagent is running when an `Agent` or `Task` call was acknowledged as launched in the background (`toolUseResult.isAsync: true`, keyed by its `agentId`) or an agent was resumed by `SendMessage` (`toolUseResult.success: true`), strictly after the prompt, and no hand-back from it (a user or `queued_command` attachment entry whose origin is `{"kind": "peer", "from": <agentId>}`), no task notification naming the call (`<tool-use-id>`), no `TaskStop` and no kernel `exit` line in its journal (written by `r__subagent-stop__proc-exit.py`) came after that launch. With no stop record the agent counts as running for at most 30 minutes (`PENDING_MAX_MINUTES`) after its launch or message. An agent from an earlier turn, a builder included, never exempts a stop unless it is messaged again in this turn. The claim-word check (`status_claim`: outcome words such as `passed`, `merged`, `done`, `arreglé`, `envié`, `erledigt`, `gelöst`, and a digit outside a provenance line) is an extra speed bump, not the boundary: a claim phrased without one of its words passes it. Each exempted stop is appended to `~/.claude/.cache/receipts/reply-pending.jsonl` with the session id and the prompt uuid; a ledger that cannot be read or written is an error.

**Fail-closed.** An unparseable payload, a payload without `last_assistant_message`, no operator prompt, an unreadable transcript, an import error, a missing helper, a receipt ledger that is not a readable file, an unreadable or unwritable `reply-pending.jsonl`, or an exception from the ledger exits 2 with the error named. A missing receipts directory is no receipt, not an error. The way out is the operator's: `panel-skip` in his own prompt for one turn, `OCTO_REPLY_PANEL=off` in the launching shell for the session. A turn opened by a compact summary carries no operator words, so `panel-skip` cannot apply there; such a turn clears with a panel receipt newer than the summary, or with the off switch. The main loop cannot set the second one: a Bash export does not reach hook processes. The harness sets `CLAUDE_CODE_CHILD_SESSION=1` in hook commands; the gate ignores it.

## Cost controls (measured)

Measured over the 35 operator turns between the v11.0.0 cut (2026-10-15T13:53Z) and 2026-10-16T08:19Z, 103 emitted replies, read-only from the session transcripts and the receipt ledger. Weighted tokens are an estimate: input-price equivalent with cache reads at 0.1x, cache writes at 1.25x and output at 5x. The reply panel cost about 32.9M of 92.2M weighted tokens (36%): reviewers 18.8M, main-loop orchestration 12.0M (an upper bound), blocked re-emissions 1.6M, failed seats 0.6M. NEEDS-WORK receipts caught 6 wrong facts and 7 overstatements on replies; a reply longer than a 30-word status line keeps its reviewer whatever its class, a status line ends a turn unreviewed only inside the per-turn bound above (a subagent of this turn, 3 stops per prompt), and the claim-word list is a speed bump inside that bound, not a boundary (R-09).

## Proof

`python3 scripts/g__stop__reply-panel.py --selftest registry/fixtures/FLOW.panel-before-reply`. Each `violation_*.json` must exit exactly 2, each `benign_*.json` exactly 0, every case in its own sandbox HOME. A case's optional `_fixture` key (stripped before the gate sees the payload) seeds receipts through `panel_fixture_seed.seed_reply_receipt`, pre-records spent ids, breaks the ledger, sets env, and asserts on stderr and on the spent ledger. The run scrubs `OCTO_REPLY_PANEL`, sets `CLAUDE_CODE_CHILD_SESSION=1`, and pins the clock to the newest transcript entry under `CLAUDE_SESSION_ID=__selftest__`, so the 120-minute window never ages the fixtures out. Two unit checks run first: the digest (AC-01) and a copy of the gate whose send gate lacks `_origin` (AC-17), which must exit 2 naming it. Every blocked case must also be journaled under `FLOW.panel-before-reply`.

`brain_doctor` covers the rule through its generic checks: `registry-wiring` (the gate in `hooks.json` at Stop), `registry-anchors` (the "Reply panel" anchor in CLAUDE.md) and `gate-liveness` (the selftest). `reply-panel-arm-env` warns when an arm settings file sets the off switch (R-10).

## External reviewers

Spec `docs/specs/202610141000-v11-harness-independence-opt-in-tracing/` phase 4 (FR-05 to FR-07, AC-18 to AC-29, AC-37, AC-38, task T19). A review run on another engine (Codex CLI, Gemini CLI) can count as one more reviewer when a hook, not the model, wrote its receipt.

- **The receipt.** `scripts/r__pretool-bash__external-review.py` (PreToolUse Bash) and `scripts/r__posttool-bash__external-review.py` (PostToolUse Bash) write a `kind: external` row to the receipt ledger around one Accepted_Review_Call: a single simple command whose first two tokens are the pinned interpreter and the pinned script by literal absolute path, with only that engine's allowlisted arguments (Codex: `exec`, `--skip-git-repo-check`, `-m NAME`, one prompt; Gemini: `-m NAME`, one `-p TEXT`), no redirect, pipe, list, expansion, subshell or raw newline outside single quotes. Before and after the call every pinned file of the engine (interpreter, launcher or script, Codex's vendor binary, Gemini's `bundle/` tree) must hash to its pin with its realpath and its ancestors' realpaths unchanged up to a pin root that is neither `$HOME` nor `/`; the shell startup files and the engine config file must hash to their pins; none of `BASH_ENV`, `ENV`, `NODE_OPTIONS`, `NODE_PATH`, nor a variable that moves a CLI's config home, settings file or endpoint (`CODEX_HOME`, `CODEX_EXEC_SERVER_URL`, `OPENAI_BASE_URL`, `OPENAI_API_BASE`, `GOOGLE_GEMINI_BASE_URL`, `GOOGLE_VERTEX_BASE_URL`, `GEMINI_API_BASE`, `GEMINI_CLI_HOME`, `GEMINI_CLI_SYSTEM_SETTINGS_PATH`, `GEMINI_CLI_SYSTEM_DEFAULTS_PATH`) may be set in the hook's environment; no unpinned workspace config (`.gemini/settings.json`, `.gemini/.env`, `.codex`) may exist from the call's cwd up to its project dir; and a Codex subcommand name (`resume`, `review`, `apply`, ...) in the prompt slot is refused. The output is copied to `~/.claude/.cache/receipts/external/<tool_use_id>.out`. Any other shape runs and never counts. Logic: `scripts/external_review.py`.
- **The pins.** `~/.claude/company/config/reviewer-pins.json`, gitignored, on the arming surface, written by the operator in a terminal from the command `python3 ~/.claude/scripts/external_review.py pin-command` prints. `external_review.py check` says whether the pins hold now. Template: `templates/company/config/reviewer-pins.json.template`.
- **What counts.** `receipt_ledger.panel_receipts_for` returns an external receipt as a reviewer whose id is its `tool_use_id` only when it is complete with exit 0, names a model, its output re-hashes and ends on a panel block that recomputes to the digest, its `tool_use_id` is a harness Bash tool_use of this session (main loop or subagent transcript) whose command re-parses to the same engine, model and prompt digest, its tool result is inside the 120-minute window, `registry/reviewers.yaml` marks the engine and model `allowed`, and the session's arm, resolved by the Export_Guard from the call's cwd together with `CLAUDE_PROJECT_DIR` (a `cd` out of a deny arm resolves to a mismatch, which denies), is none or `allow`.
- **The bound.** The reply gate sets every external PASS aside, requires the newest remaining receipt to be a harness reviewer's PASS newer than the prompt, and only then counts the external receipts as distinct reviewers, so a harness PASS revoked by a newer NEEDS-WORK never anchors a quorum; `panel_pass_for`, which the send gate and the sent-message ledger read, drops every external PASS before the newest receipt decides, so an external NEEDS-WORK can revoke and an external PASS never clears a send. `python3 scripts/receipt_ledger.py --selftest-external` seeds forged complete receipts and proves both (AC-38).
- **QA and panel receipts.** A reviewer subagent that ran an external review names it on a `REVIEW-EXTERNAL: <tool_use_id>` line; `r__subagent-stop__qa-receipt.py` adds that engine and model to its receipt as `external_reviewers`, leaving the agent type, the verdict and the merge gate's requirements unchanged.
- **What stays open.** The prompt is written by the model, so a "review" can be an instruction to echo a PASS block; the CLIs also read context files (`AGENTS.md`, `GEMINI.md`) and `.env` files the receipt does not check. Both are bounded only by the rule above: one vote beside a required, standing harness PASS, never a send.
- **Not runtime support.** An `allowed` reviewer pair says nothing about Codex CLI or Gemini CLI as runtimes; their status in `registry/runtimes.yaml` comes only from their census records (FR-07).
