# Octorato v9: Done Is a Verdict

> v7 made a send without receipts impossible. v8 made a run a process. v9 makes "done" a verdict computed against a spec by a pass that did not write the code, never a claim typed by the agent that did.

Spec and plan: `docs/specs/202609301321-v9-done-is-a-verdict/`.

## The problem

Before v9 the SDD flow let the builder grade itself. `sdd-implement` wrote `impl-summary.md` with `[x] AC-01: Passed`, and `sdd-review` ticked the acceptance criteria in `feature.md`. Both were completion claims made by the process that wrote the code, and nothing could check them, because acceptance criteria were free prose.

## The contract

A LARGE task is done when, and only when, an independent verifier on the judgment tier has judged every acceptance criterion against the code and tests and returned `CONVERGE-VERDICT: CONVERGED` for that spec directory, and nothing outside the spec directory has changed since.

Three layers carry it.

| Layer | Mechanism | What it makes true |
|---|---|---|
| A spec a script can read | `Spec-Format: ears-1`: EARS criteria with a Glossary subject, at most 3 open markers, tasks as `T## [AC-##] <path>: <action>`. Checked by `scripts/spec_lint.py`, stdlib only | Coverage is computed, not judged. Rule `FLOW.spec-contract` |
| Verdict skills | `sdd-analyze` (spec against plan, read-only, before code) and `sdd-converge` (code against criteria, append-only, after code), both independent verifier subagents | The builder never grades its own work |
| Receipt and gate | The SubagentStop reflex `r__subagent-stop__qa-receipt.py` records `CONVERGE-VERDICT` and `CONVERGE-SCOPE` as a `converge` receipt; `.githooks/pre-push` runs `spec_lint.py --push-range` per pushed ref | A spec cannot reach `Status: converged` in a push without a fresh CONVERGED receipt. Rule `FLOW.done-is-a-verdict` |

### The spec home

Every ears-1 spec is created in `docs/specs/<yyyymmddHHMM>-<feature-name>/` and never moves. That path is the key of the converge scope, the receipt and the push gate. A spec that moved at archive time gave them three different paths, so no receipt could ever match (operator decision, 2026-09-30).

### What the push gate checks

For every pushed ref, `spec_lint.py --push-range <base> <head>` reads the specs the push changes. The pushed head is compared, as one tree diff, with its merge base with the default remote branch, so the check covers what the branch changes and runs again on every push of it. That choice does two things. A spec that converged on the default branch through its own pull request and reaches another branch by merge or rebase is not that branch's flip. And a flip already pushed stays in the comparison, so code pushed after it meets the freshness check again. Without a default remote branch the comparison falls back to what the remote ref holds. Submodule changes are always listed, whatever `diff.ignoreSubmodules` or a tracked `.gitmodules` says. Commit order and merge commits do not matter to that comparison: an earlier version walked the commits one by one, missed a spec edited inside a merge commit, and read the "before" state off commit dates (converge pass 1 found both). A spec is a `feature.md` in its own directory directly under `docs/specs/` or `docs/specs-archive/`, at any depth of the repository; a `feature.md` nested deeper (`docs/specs/<name>/v2/feature.md`), test fixtures and templates are not specs and are never read, because violation fixtures are malformed on purpose. A `docs` directory, a spec home, a spec directory or a spec file must be a plain file or directory in the git tree, at any depth: no symlink, no submodule, and no other tree mode. The gate reads the tree, and a link or a submodule would hide specs that a filesystem walk (the doctor, an editor, a person) still sees on disk. A link or submodule with any other name hides nothing the gate reads, because a spec in the tree sits at its real path. The rule is broad on purpose: a vendored symlink named `docs`, or a convenience link inside a spec home or a spec directory, is refused too. Spec paths are matched without regard to case, and any spelling other than the lower-case `docs/specs/<name>/feature.md` (or `plan.md`, or `docs/specs-archive`) is refused, because on a case-insensitive filesystem (Windows, macOS by default) another spelling lands on the same file. A spec file may not be a Git LFS pointer, which would hide the spec the same way. Deleting a spec is allowed, a miscased one included, so a bad spelling can be removed or renamed. For each spec it:

1. lints, at the pushed head, every ears-1 spec whose `feature.md` or `plan.md` the push changes (AC-15). Only `ears-1` opts a file in: a header naming another version does not declare this format, and the linter skips that file like a legacy spec (AC-16). The headers are part of the lint: every header-shaped `Status` or `Spec-Format` line, in any markup, must be the canonical `> **Status:** draft|approved|converged` and `> **Spec-Format:** ears-1`, exactly once, in the first 30 lines. The gate reads only the canonical form, so any other form is a finding, never an unseen flip;
2. refuses a spec that stops being ears-1 in the push (its Spec-Format header removed, broken or changed to another version), in place or by moving: a push that removes an ears-1 spec may not add a spec without the header, nor any `feature.md` outside a spec directory (one level deeper, or outside the spec homes), where the gate would no longer read it, and a spec directory under `docs/specs/` not named `<yyyymmddHHMM>-<lowercase-slug>`;
3. refuses a spec that says `converged` without a `plan.md`, flip or not;
4. for every ears-1 spec whose `Status` becomes `converged` in the push, requires the latest anchored converge receipt for that exact spec directory to say `CONVERGED` (a later `GAPS` makes an earlier `CONVERGED` stale) and to be newer than the newest code commit on the branch (AC-14).

"Newer" compares the harness-written timestamp of the transcript entry that carries the verdict, never the ledger line's `ts`, against the latest author or committer date among the commits that are on this branch (reachable from the pushed head, not from the default remote branch) and touch a path outside the spec directory. Branch scope closes the two-push split, where code went out in one push and the status flip in the next. Both dates count because each alone is slipped by an everyday command: `git commit --amend` and `git cherry-pick` keep the old author date, and only the committer date shows when the code landed. The cost, accepted: a rebase after the verdict stales it, and so does merging the default branch into the spec's branch (the merge commit is on the branch and master's code entered it unseen by the verifier); the converge pass runs again. That concerns only the push that flips a spec, once per spec. A spec that already says `converged` and has no `plan.md` is refused on any edit, so its first edit restores the plan.

What the gate reads as a header is the header-shaped line at the start of a line. A plain sentence that begins with `Status: converged` at the start of a line is read as a second, non-canonical header and refuses the push; reword it or quote it in backticks. Conversely a status shown only inside an HTML comment, a heading or a later table cell renders for a reader but is not a header, and the gate reads the canonical line.

A receipt is anchored the same way a QA receipt is: written by the harness-side reflex, pointing at a harness-written agent transcript under the projects directory whose last report re-parses to the same verdict and scope, from a verifier persona. A scope must equal the spec directory exactly; a prefix never matches. The gate reads receipts from any session on the machine, because a push runs outside any session.

### What the doctor checks

`brain_doctor` check `spec-contract` lints every ears-1 spec on disk and confirms the pre-push stanza. It confirms the stanza is the condition of an `if !` whose body reaches `exit 1`, and warns, never fails, for a spec that says `converged` with no CONVERGED receipt on this machine. It reads status with the gate's own function. The two gate rules prove their fixtures through `gate-liveness`.

| A transcript can be forged under `$HOME` | Same residual v7 states: agent transcripts are files the model can append to | A forged receipt needs a harness-shaped entry in the right session directory under the right agent id. | Commit dates are set by whoever commits | An amend or a cherry-pick alone no longer slips code under a verdict, since the committer date counts. One rebase flag does: `git rebase --committer-date-is-author-date` after amending new code sets the committer date back to the old author date. A machine whose clock runs behind does the same by accident | It needs a deliberate flag or a wrong clock, and the commit still shows in the branch's history; the verdict's own timestamp comes from the harness, not the commit |
| Code merged to master outside the branch is not counted | Freshness looks at the branch's own commits, so a code change that reached master through another PR before the flip is outside the comparison | That code went through its own PR and QA; the spec's criteria are re-judged the next time its code changes on a branch |
| Every push is compared with the default branch | A branch stacked on another branch that already flipped a spec has that flip in its own diff, and a branch that pushes code after its own flip is asked again | It blocks rather than allows; the converge pass runs once more on that branch |
| The default remote branch is a local ref | `git update-ref refs/remotes/origin/<default>` onto the pushed head leaves an empty comparison, and the check sees nothing | A deliberate local disarm, the same kind as `--no-verify` from a worktree, with the same bound: the merge gate and the doctor's WARN |
| A Spec is a file named `feature.md` | A spec renamed to another file name (`spec.md`) in a push passes, and so does a copy that says converged while the original stays approved | The linter, the doctor and every skill key on `feature.md`, so the renamed file is no longer a spec to any of them; the copy is not the Spec |
| A spec's content can land on an existing `feature.md` | A push that removes an ears-1 spec and writes its content over a `feature.md` that already existed outside a spec directory passes: git reports a deletion and a modification, and the check only reads files the push adds. Measured by converge pass 4 and the final QA of #339 | The file is not a spec to the linter, the doctor or any skill, so no Spec reads `converged` without a verdict; the same class as the file-name row |
| A branch that removes a spec cannot add an unrelated `feature.md` outside a spec directory | The rule that stops a spec leaving the gate by moving pairs by "one removed, one added", not by content, so a branch that deletes an ears-1 spec and adds a new test fixture `feature.md` is refused | A false block in the safe direction, and the message names the remedy: land the removal in its own pull request |
| A spec can leave ears-1 across two pull requests | Deleting an ears-1 spec in one pull request and, once that is on the default branch, adding a file without the header in another passes; each half is allowed on its own. On one branch both halves are in the same comparison and the push is refused, also when the two files are unrelated | The file is then a legacy spec the linter skips, and it reaches the default branch only through a reviewed pull request |
| Several remotes, no `origin/HEAD` | The default branch is every `*/main` and `*/master` ref, and the first merge base found wins. A second remote with an older default branch makes the default branch's own converged specs read as a flip | It blocks rather than allows. `git remote set-head origin -a` names one default branch; this repository has one remote |
| A stale default remote ref | With the local `origin/<default>` behind the commit a branch was cut from, a spec converged in between reads as the branch's flip | It blocks rather than allows, and the message says to fetch |
| A repository with no default remote branch | The comparison falls back to what the remote ref holds, so a spec converged elsewhere reads as a flip and code pushed after a pushed flip is not re-checked | Applies to a fresh mirror or a remote without `main` or `master`; this repository has one |
| A first push of a whole history | With no remote-tracking refs (a fresh mirror) there is no before state, every file counts as changed and every converged spec reads as a new flip | It blocks rather than allows; push the history with the receipts present, or push the flips separately |
