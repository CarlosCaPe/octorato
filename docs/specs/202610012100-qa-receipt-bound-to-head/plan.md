# Implementation Plan: A QA verdict is bound to the commit it reviewed

> **Spec:** `feature.md` in this directory (`Spec-Format: ears-1`)
> **Date:** 2026-10-01

## Overview

One pull request. The ledger learns the commit and the newest-verdict lookup first, the reflex records the commit, the gate reads the pin from the command's arguments and decides, and the rule text follows. Every step has a test that fails without it.

## Architecture Decisions

- **The merge command carries the commit; the gate never asks GitHub.** On a direct merge GitHub refuses a head that differs from the pin (`expectedHeadOid` on `mergePullRequest`, REST `sha` with a 409). The gate compares the pin with the reviewed commit and stays inside its 5 second budget with no network call.
- **Direct merges only.** `--auto` sends the pin to `enablePullRequestAutoMerge`, where a re-check at merge time is not established, so an approved merge with `--auto` is refused rather than trusted.
- **The pin is read the way gh reads it.** The sub-command is split with `shlex`, then walked with gh's value-flag table for `pr merge` and for `api`: a flag that takes a value consumes the next token (or its `=` / attached short form), whatever that token looks like, and in a short cluster `-xyz` the first value letter takes the rest of the token or the next token, so the pin is only ever the value of the pin flag itself. Last pin wins, as in gh. On the REST path the pin is the value of a field flag reading `sha=<commit>`. A body the gate cannot read as arguments (`--input`, `curl -d`, JSON) is unpinned, so it blocks.
- **The lookup is bounded.** Ledger rows are narrowed by `kind` and pull request scope before any transcript is read, never by the ledger's own commit, so the transcript decides the commit and the verdict. Only regular files are opened. The gate runs the lookup in a daemon thread and joins it for 3 seconds; on timeout it blocks and returns, and the daemon thread ends with the process. Works on POSIX and Windows alike, with no signal.
- **The reviewer declares the commit.** `QA-HEAD: <sha>` is a third protocol line in the reviewer's final report, re-read from the agent transcript like the verdict and the scope.
- **A receipt is anchored to its own entry.** The reflex stores the harness `uuid` and `timestamp` of the transcript entry it parsed. A consumer finds that entry by `uuid`, re-reads verdict, scope and commit from it, and skips the receipt when they differ from the ledger row or the entry is gone. A resumed reviewer's later reply cannot change what an earlier receipt says. Receipts are ordered by that entry's timestamp, never by ledger order, and come from every session.
- **Old receipts open nothing.** A receipt without a commit cannot match a pin, so a pull request reviewed before this change needs one more pass. Actions with no pull request number keep `qa_pass_for` and today's rule.
