# Feature: harness independence and opt-in tracing (next v11 minor)

> **Status:** draft
> **Spec-Format:** ears-1
> **Date:** 2026-10-14
> **Classification:** LARGE (score 9: 4 to 10 files, new feature, architecture decision, multiple modules)

Octorato's brain is plain files, but today it runs on two harnesses: Claude Code and Cursor. This minor release adds the harnesses that block a tool call from a hook, and an opt-in trace view per arm that can never upload from an arm that forbids it. It does not add LangChain or LangGraph.

## Summary

**Why harnesses, not a model library.** A research pass on 2026-10-14 (deep-research run `wf_0e7bf9d3-12e`, 24 of 25 claims confirmed by 3-vote verification) compared LangChain 1.x and LangGraph 1.x with Octorato. Model independence in Octorato does not live in code: the harness picks the model, and `docs/architecture/multi-runtime.md` maps four vendor-agnostic tiers onto each harness's model slugs. The command `grep -rlE "import (openai|anthropic)|from (openai|anthropic)|google\.generativeai|litellm|api\.openai\.com|api\.anthropic\.com" scripts skills --include=*.py` (vendored packages excluded) returns 7 files: `scripts/anthropic-analytics-pull.py`, `scripts/finops-digest.py`, `skills/image-analyzer/scripts/analyze_image.py`, `skills/speech/scripts/text_to_speech.py`, `skills/imagegen/scripts/image_gen.py`, `skills/sora/scripts/sora.py`, `skills/transcribe/scripts/transcribe_diarize.py`. Two read Anthropic usage and cost; five use vendor-specific media features. None gains from a model abstraction library, so independence grows by adding harnesses.

**Which harnesses.** Gemini CLI documents `BeforeTool` hooks in `.gemini/settings.json` (project) and `~/.gemini/settings.json` (user) that block with exit code 2 and use stderr as the reason, or with a JSON `deny` decision; its payload carries `tool_name`, `tool_input` and `mcp_context`, and MCP tools are named `mcp_<server>_<tool>` (geminicli.com/docs/hooks/reference). The same site states that Gemini CLI "was replaced by Antigravity CLI on June 18th, 2026" for unpaid and Google One tiers. OpenAI Codex CLI documents `PreToolUse`, `PostToolUse`, `Stop` and nine more events, configured in `~/.codex/hooks.json` or `[hooks]` tables in `config.toml` at user or repository level; it blocks with `permissionDecision: deny` or exit 2 with a stderr reason; `PreToolUse` covers shell (matched as `Bash`), `apply_patch` edits, MCP and local tools, but not hosted tools; hooks are on by default, and hooks not set by a managed policy must be trusted through `/hooks` before they run (learn.chatgpt.com/docs/hooks). Neither harness is accepted until the census measures it.

**Why tracing, and why off.** LangSmith ships an official Claude Code plugin (`langsmith-tracing`) that sends each turn as a trace: user messages, tool calls, compaction and subagent runs. It is switched on by `TRACE_TO_LANGSMITH` in a project's `.claude/settings.local.json`, in the global `~/.claude/settings.json`, or as a shell export. Secret redaction is on by default, and the same page calls it "a safety net rather than a guarantee" (docs.langchain.com/langsmith/trace-claude-code). Arms hold client data, and at least one arm has a signed commitment not to export real data outside the client's tenant. So tracing must be off unless an arm explicitly allows it, the decision must be read from the arm at send time, and the upstream hook must not run at all when the arm says no.

**Why reviewers on other engines, and why a receipt (phase 4).** The judgment tier prefers "a **different vendor** than the builder when available" (`docs/architecture/multi-runtime.md`, judgment row), yet every receipt the ledger honours is written for a harness subagent: a panel receipt needs an agent type matching `PANEL_AGENT_TYPE` and a harness-shaped agent transcript of the same session (`scripts/receipt_ledger.py`, `panel_receipts_for`), and a QA receipt is written by `scripts/r__subagent-stop__qa-receipt.py` from a subagent's final report. A review run through `codex exec` or `gemini -p` counts today only when a Claude subagent quotes it, so the receipt belongs to the Claude subagent; the v11 reply panel states the gap as R-05, "The reviewer is independent in context, not in model" (`docs/architecture/v11-reply-panel.md`). Phase 4 adds a receipt written by a Bash hook pair around the external call. What that receipt proves is narrow, and the criteria say only that: one simple command named a pinned interpreter and a pinned script by their literal absolute paths, the checked files hashed to their pins before and after the call, the shell startup files hashed to their pins and no `BASH_ENV` or `ENV` was set, and the call took this exact prompt, asked for this model and produced this exact output. It proves the hashes of the files it checked, not that the hashed bytes were the bytes executed, not which model the vendor served, and not that the modules and config the CLI loads were unchanged. Both CLIs on the measuring machine are Node scripts behind `#!/usr/bin/env node` (`codex` resolves to `@openai/codex/bin/codex.js`, `gemini` to `@google/gemini-cli/bundle/gemini.js`; `readlink -f`, 2026-10-16), at versions `codex-cli 0.159.3` and `gemini 0.62.0`. In `codex exec` the flag `-m` names the model and `-p` a config profile, while for `gemini` `-p` is the prompt, so the command parser is per engine. An engine is not trusted by assumption either: the local ledger holds 127 panel NEEDS-WORK and 470 panel PASS receipts (read-only count of the gitignored `~/.claude/.cache/receipts/global.jsonl`, 2026-10-16), and the v11 cost measurement credits NEEDS-WORK receipts with 6 wrong facts and 7 overstatements caught over 103 replies, so an engine joins a quorum only on a replayed catch rate, and that score is a screen, not evidence of its catch rate in real reviews. Codex CLI and Gemini CLI stay `gap` as runtimes (AC-03): reviewing text is not running Octorato's gates.

## Glossary

Every acceptance criterion names one of these components as its subject.

- **Runtime_Registry**: a new tracked file `registry/runtimes.yaml`, one entry per harness with its instruction file, hook config path, block contract, tool-name map, tier binding, unprojected gates, and a status of `supported` or `gap`.
- **Runtime_Census**: a new script `scripts/runtime_census.py`. For each harness it feeds the Block_Fixtures as that harness's documented hook payloads (deterministic), and runs one live end-to-end call per harness from a sandbox prompt with no client data. It writes one tracked record per harness to `registry/census/<harness>.json`.
- **Block_Fixture**: a tool call that a projected gate must deny, plus its benign twin derived by one edit, both taken from that gate's existing `registry/fixtures/` directory.
- **Hook_Shim**: a new script `scripts/g__shim__hook.py` that translates a harness's hook payload into the fields a gate reads, and the gate's deny into the harness's block.
- **Hook_Projector**: one new script per supported harness, `scripts/merge-hooks-gemini.py` and `scripts/merge-hooks-codex.py`, following `scripts/merge-hooks-cursor.py` and its tool-name map.
- **Instruction_Sync**: the `sync-ai-docs` step of `scripts/ai_sync.py`, extended to write `AGENTS.md` and `GEMINI.md`.
- **Arm_Resolution**: the arm of a session is the registered arm path (from `company/config/arms-paths.json`, candidate arrays resolved as `load_arms()` does) whose real path contains the real path of the session's working directory. A brain session or a working directory under no registered arm resolves to no arm.
- **Export_Policy**: a new optional field `telemetry.export` in an arm's `arm.json`, with values `deny` or `allow`.
- **Tracing_Wrapper**: a new Octorato plugin package of kind `plugin` whose hook commands call the Export_Guard; it carries the upstream LangSmith plugin's hook scripts unmodified.
- **Export_Guard**: a new script `scripts/g__wrap__export-guard.py`, called by every Tracing_Wrapper hook command, that applies the Export_Policy of the session's arm and starts the upstream hook script only on `allow`.
- **Export_Flip_Gate**: a new PreToolUse gate `scripts/g__pretool__export-flip.py` that guards writes to `telemetry.export`.
- **Arming_Gate**: `scripts/g__pretool__arming-surface.py`, the v8 gate that denies writes to the live copy of the files that arm the gates.
- **Package_Installer**: `scripts/octo_pkg.py`.
- **Doctor**: `scripts/brain_doctor.py`.
- **Reviewer_Pins**: a gitignored per-machine file `company/config/reviewer-pins.json`, written by the operator in a terminal from a command the agent prints. Per External_Reviewer_CLI it holds the absolute path, realpath and SHA-256 of the interpreter (`node`) and of the script (for example `codex.js`), and a pin root directory for each; once per file it holds the SHA-256 of the shell startup files `~/.bashrc`, `~/.bash_profile` and `~/.profile` at pin time (absent recorded as absent).
- **External_Reviewer_CLI**: a reviewer command with its engine, its model argument and its prompt sources, listed in the Reviewer_Registry and pinned in the Reviewer_Pins.
- **Accepted_Review_Call**: a Bash command whose raw text, outside single-quoted spans, holds no newline, no `<<` (heredoc or here-string), no `>` (so no `>>`), and none of `&`, `|`, `;`, `$`, backtick, `(`, `)`, `{`, `}`, and holds `<` at most once; which `shlex.shlex(command, posix=True, punctuation_chars=True)` splits into tokens whose first equals, as a literal string, the pinned interpreter path of one External_Reviewer_CLI and whose second equals, as a literal string, its pinned script path (no glob, tilde or expansion is resolved before the comparison); with no `NAME=value`, `env`, `alias`, `command`, `builtin` or `exec` token before the interpreter; and whose only redirect is at most one trailing `< file`.
- **External_Review_Reflex**: a new hook pair, `scripts/r__pretool-bash__external-review.py` (PreToolUse Bash) and `scripts/r__posttool-bash__external-review.py` (PostToolUse Bash), that never blocks and fails open, like `scripts/r__subagent-stop__qa-receipt.py`.
- **External_Review_Receipt**: a ledger line of kind `external` in `~/.claude/.cache/receipts/global.jsonl`, written only by the External_Review_Reflex around one Accepted_Review_Call.
- **Reviewer_Registry**: a new tracked file `registry/reviewers.yaml`: the External_Reviewer_CLI entries without machine paths, and one entry per engine and model pair with a quorum status of `allowed` or `not-allowed`, the Replay_Record it rests on and the baseline model of that record.
- **Panel_Ledger**: the panel functions of `scripts/receipt_ledger.py` (`panel_receipts_for`, `panel_latest_for`, `panel_pass_for`).
- **Reply_Panel_Gate**: `scripts/g__stop__reply-panel.py`, which counts the reply quorum as distinct PASS agent ids over `panel_receipts_for`.
- **Send_Gate**: `scripts/g__pretool-mcp__outward-send.py`, which reads `panel_pass_for` before a message send; `scripts/r__posttool__sent-ledger.py` reads the same function to spend the receipt.
- **QA_Receipt_Reflex**: `scripts/r__subagent-stop__qa-receipt.py`, the SubagentStop reflex that writes `qa`, `converge` and `panel` receipts.
- **Replay_Fixture_Set**: a new tracked directory `registry/replay/fixtures/` of synthetic panel cases with a known expected verdict.
- **Held_Out_Set**: an optional private directory `company/replay/held-out/` of panel cases in the Replay_Fixture_Set's format, gitignored with the rest of `company/`.
- **Replay_Harness**: a new script `scripts/review_replay.py` that runs the Replay_Fixture_Set through one engine and model.
- **Replay_Record**: a tracked file `registry/replay/records/<engine>-<model>.json` written by the Replay_Harness.

## User Stories

- As the operator, I want Octorato to run with the same gates on a second harness, so that switching vendor is a choice and not a rebuild.
- As the operator, I want to see a session's turns, tool calls and subagents as a trace when I debug, so that I stop reading transcripts by hand.
- As a client, I want my data never to reach a third-party trace service unless my project allows it, so that the consultant's tooling does not break what we signed.

## Functional Requirements

### FR-01: A harness is supported only when it blocks

A harness becomes `supported` only after the Runtime_Census shows it blocking the shell, file write and file edit classes. Anything less is a `gap` with the classes it does not block. Claude Code and Cursor keep their status on their existing evidence.

### FR-02: The same gates, projected and shimmed

Each supported harness gets a Hook_Projector that writes its hook config from `hooks.json` through a per-harness tool-name map, and every projected gate runs through the Hook_Shim. A gate that cannot be projected is listed by matcher token, never dropped silently.

### FR-03: Each harness reads the brain in its own file

The Instruction_Sync writes the arm instructions to the file each supported harness reads, from the same `CLAUDE.md` source of truth, with the same commit convention as `.cursorrules`.

### FR-04: Tracing is a per-arm opt-in that defaults to off

An arm that says nothing is `deny`. The upstream tracing hook runs only for a session whose arm is `allow`; only the operator flips an arm to `allow`; and a tracing failure never blocks a turn and stays within a measured bound.

### FR-05: A review on another engine is receipted by a hook at a pinned boundary

A review run through a pinned interpreter and script, as one simple command, leaves a receipt that a hook wrote, binding the hashes of the checked files, the requested model, the exact prompt and the exact output, so a panel or QA verdict can name that engine without a Claude subagent owning the receipt. Any other shape of call still runs and never counts.

### FR-06: An engine joins a quorum on a measured catch rate

An engine and model pair counts toward a panel quorum only when its worst catch rate over three runs on a tracked, synthetic replay set is within a stated bound of the judgment-tier baseline, and never forms a quorum alone. The existing minimum quorum sizes (3 for a SELF reply, 1 for a SOURCED or INPUT reply) and the distinct-reviewer rule are unchanged.

### FR-07: Reviewing is not running

Phase 4 changes no runtime status. Codex CLI and Gemini CLI stay `gap` until their census records show shell, file write and file edit blocked (FR-01); a reviewer receipt or a replay record is not evidence for that.

## Acceptance Criteria

- [ ] AC-01: THE Runtime_Registry SHALL hold one entry per row of the "Runtimes" table of `docs/architecture/multi-runtime.md`, and THE Doctor SHALL fail when a harness appears in one and not the other or when their statuses disagree.
- [ ] AC-02: WHEN the Runtime_Census runs for a harness, THE Runtime_Census SHALL record, for each of the shell, file write, file edit and MCP tool classes, whether the documented-payload Block_Fixture was blocked and its benign twin allowed, the result of one live end-to-end call, and the harness binary, version and account tier it ran against.
- [ ] AC-03: THE Runtime_Registry SHALL mark Gemini CLI or Codex CLI `supported` only when its record in `registry/census/` shows the shell, file write and file edit classes blocked and their benign twins allowed, and SHALL otherwise mark it `gap` and list the classes that did not block; Claude Code and Cursor SHALL keep `supported` on the evidence of the gate selftests and the Doctor's Cursor hook-sync check; and THE Doctor SHALL fail when a Gemini CLI or Codex CLI entry is `supported` without a census record that satisfies this criterion.
- [ ] AC-04: WHERE a harness is `supported`, THE Hook_Projector SHALL write that harness's hook configuration from `hooks.json` through the harness's tool-name map, projecting only events and tool classes its census record shows as blocking, and SHALL write every matcher token it did not project into that harness's Runtime_Registry entry.
- [ ] AC-05: WHEN a projected fail-closed gate denies, THE Hook_Shim SHALL make the harness block the call with the gate's reason, and IF the Hook_Shim cannot parse the payload for a fail-closed gate, THEN THE Hook_Shim SHALL block the call.
- [ ] AC-06: WHEN the `--selftest` of a projected fail-closed gate runs through the Hook_Shim under a `supported` harness, THE Hook_Shim SHALL make the harness block the violation leg and allow the benign leg.
- [ ] AC-07: THE Instruction_Sync SHALL read the Runtime_Registry and write `AGENTS.md` for Codex CLI and `GEMINI.md` for Gemini CLI in each arm only for harnesses marked `supported`, from that arm's `.claude/CLAUDE.md`, and a second run with no source change SHALL leave every file byte-identical.
- [ ] AC-08: WHERE a harness is `supported`, THE Runtime_Registry SHALL map the four tiers (mechanical, bulk, build, judgment) to that harness's model slugs.
- [ ] AC-09: IF an arm's `arm.json` has no `telemetry.export` field, THEN THE Export_Guard SHALL treat the arm's Export_Policy as `deny`.
- [ ] AC-10: IF the Arm_Resolution of the session finds no arm, or finds an arm whose Export_Policy is `deny`, THEN THE Export_Guard SHALL exit 0 with no output, which every harness event treats as a no-op, without starting the upstream hook process.
- [ ] AC-11: WHERE the session's arm has Export_Policy `allow`, THE Export_Guard SHALL start the upstream hook script with its original input and environment, with redaction left on.
- [ ] AC-12: THE Doctor SHALL fail when the tracing switch is set in the project settings of an arm whose Export_Policy is `deny` or absent, or in the global settings while any registered arm has Export_Policy `deny` or absent.
- [ ] AC-13: THE Package_Installer SHALL install the Tracing_Wrapper as kind `plugin` with a verified signature and a lock entry, disabled for every arm on install, run by the operator in a terminal outside any session from a command the agent prints, the agent never enabling a plugin itself; and THE Doctor SHALL fail when the installed wrapper tree does not hash to its lock entry or when the upstream `langsmith-tracing` plugin is installed in `~/.claude/plugins` outside the Tracing_Wrapper.
- [ ] AC-14: WHEN LangSmith is unreachable, measured once with the endpoint pointed at a closed local port and once at a non-routable address, THE Tracing_Wrapper SHALL let the turn finish and SHALL add, for every hook event it registers (read from the upstream plugin's hook list at measurement time), at most 50 ms at the median and 200 ms at p95 to the wall time of that event's hook list, against the same list without the wrapper, over 100 consecutive events, with the upstream plugin version recorded.
- [ ] AC-15: WHEN a pull request of this spec merges, THE Doctor SHALL report the brain WIRED, with every new script, gate and reflex it ships registered in `registry/rules.yaml`.
- [ ] AC-16: IF a write would set an arm's `telemetry.export` to `allow`, THEN THE Export_Flip_Gate SHALL deny it, leaving the flip to the operator's own hand.
- [ ] AC-17: THE Arming_Gate SHALL treat `scripts/g__shim__hook.py`, `scripts/g__wrap__export-guard.py`, `registry/runtimes.yaml`, the installed Tracing_Wrapper tree and the plugin registration files under `~/.claude/plugins/` (including `known_marketplaces.json`) as live arming files, with a violation fixture writing the live copy and a benign fixture writing a worktree copy, or, for the gitignored paths under `~/.claude/plugins/`, writing the same relative path under the temporary HOME that `gate_selftest.py` provides.
- [ ] AC-18: WHEN a Bash tool call's command is an Accepted_Review_Call, THE External_Review_Reflex SHALL append from PreToolUse a pending External_Review_Receipt with the engine, the pinned path, the requested model, the prompt digest, the harness `tool_use_id` and the session id, and SHALL complete it from PostToolUse for the same `tool_use_id` with the SHA-256 of the full output, the exit code and a copy of the output at `~/.claude/.cache/receipts/external/<tool_use_id>.out`, without ever blocking the call.
- [ ] AC-19: THE External_Review_Reflex SHALL complete a receipt only when, in the Pre hook before the call and again in the Post hook after it, the SHA-256 of the pinned interpreter and of the pinned script each equal their pins, the realpath of each pinned path equals its pinned realpath, and no directory from each pinned path up to its pin root is a symlink whose realpath differs from the pinned realpath.
- [ ] AC-20: IF a command reaches an External_Reviewer_CLI by any shape other than an Accepted_Review_Call (a shell function, an alias, a `PATH=` or other assignment prefix, an `env` wrapper, a bare name resolved from PATH, the script path called alone through its shebang, a compound command, an unquoted expansion, a heredoc, a here-string, an output redirect, a raw newline), or the AC-19 check fails, or the Pre hook's own environment carries `BASH_ENV` or `ENV`, or the SHA-256 of a shell startup file differs from the value the Reviewer_Pins recorded at pin time, THEN THE External_Review_Reflex SHALL write no complete receipt until the cause is gone or the operator re-pins, and SHALL leave the call to run.
- [ ] AC-21: THE External_Review_Reflex SHALL pass a selftest whose violation fixtures (a function definition `codex(){ ...; }; codex exec ...`, an alias, a `PATH=/tmp/fake:$PATH` prefix, an env assignment prefix, a bare `codex` name with a shadow binary first on PATH, a compound command, a pinned-hash mismatch, a swapped interpreter at the pinned `node` path, a symlink at the pinned path to a byte-identical script copy beside other modules, the pinned script called alone through its `#!/usr/bin/env node` shebang, `BASH_ENV` set in the hook environment, a changed `~/.bashrc`, a heredoc and a raw newline) each yield no complete receipt, and whose benign fixture, derived from one violation by one edit, yields exactly one complete receipt.
- [ ] AC-22: THE External_Review_Reflex SHALL record as `requested_model` the value of the command's explicit model argument (`-m` or `--model`, or a Codex `-c model=` override) and `unknown` when the command names none.
- [ ] AC-23: THE External_Review_Reflex SHALL compute the prompt digest over the literal argv element the per-engine parser names as the prompt (the positional prompt of `codex exec`, the `-p` or `--prompt` value of `gemini`) followed by the bytes of the file a trailing `<` redirect names, hashing that file in the Pre hook and again in the Post hook, and SHALL record an empty prompt digest when no prompt is found or the file's hash changed.
- [ ] AC-24: THE Panel_Ledger SHALL return an External_Review_Receipt from `panel_receipts_for`, as a reviewer whose id is its `tool_use_id`, only when it is complete with exit code 0, a `requested_model` other than `unknown` and a non-empty prompt digest, its stored output re-hashes to its output digest and ends on a panel block whose recomputed digest equals the requested digest, its `tool_use_id` is a Bash `tool_use` in this session's transcript, its PostToolUse time is inside the 120-minute window, and the Reviewer_Registry marks its engine and model `allowed`, with the newest-decides and NEEDS-WORK-revokes rules unchanged.
- [ ] AC-25: THE Reply_Panel_Gate SHALL keep its minimum quorum sizes and its distinct-reviewer count, count an External_Review_Receipt as one distinct reviewer by its `tool_use_id`, and report a quorum met only when at least one counted PASS newer than the prompt comes from a harness reviewer subagent, so an External_Review_Receipt adds to a quorum and never forms one alone.
- [ ] AC-26: WHEN `panel_pass_for`, which the Send_Gate and the sent-message ledger read, decides a digest, THE Panel_Ledger SHALL first drop every External_Review_Receipt whose verdict is PASS, then let the newest of the remaining receipts (harness PASS, harness NEEDS-WORK, external NEEDS-WORK) decide, a NEEDS-WORK winning an equal or unreadable time as `panel_receipts_for` orders it today (`scripts/receipt_ledger.py`, `panel_latest_for` and `panel_pass_for`, lines 1224 to 1235), and return it only when it is a harness PASS.
- [ ] AC-27: IF the Arm_Resolution of the session finds an arm whose Export_Policy is not `allow`, THEN THE Panel_Ledger SHALL return no External_Review_Receipt of that session.
- [ ] AC-28: WHEN a reviewer subagent's final report carries a `REVIEW-EXTERNAL: <tool_use_id>` line naming an External_Review_Receipt whose `tool_use_id` is a Bash `tool_use` in this session's transcript, that passes every AC-24 check other than the digest match, whose session passes AC-27 and whose stored output ends on the same verdict as the report, THE QA_Receipt_Reflex SHALL add that receipt's engine and `requested_model` to the `qa` or `panel` receipt it writes as `external_reviewers`, leaving the receipt's agent type, verdict and every qa-merge-gate requirement unchanged.
- [ ] AC-29: THE Doctor SHALL derive the Runtime_Registry status of Codex CLI and Gemini CLI only from their census records as AC-03 states, so an `allowed` Reviewer_Registry entry or a Replay_Record for either engine leaves its runtime status `gap` until its census record shows shell, file write and file edit blocked.
- [ ] AC-30: THE Replay_Fixture_Set SHALL hold at least 40 cases whose expected verdict is NEEDS-WORK, at least 15 of them wrong facts and at least 15 overstatements (the two classes the v11 cost measurement names), and at least 40 cases whose expected verdict is PASS, each with a synthetic reply body, the source excerpts the reviewer is given, the expected verdict and, for a NEEDS-WORK case, its defect class and the line that carries the defect, written from the defect classes of historical NEEDS-WORK receipts and never copied from a transcript, an arm or the ledger.
- [ ] AC-31: WHERE a Held_Out_Set exists, THE Replay_Harness SHALL run it with the same procedure as the Replay_Fixture_Set and SHALL write to the Replay_Record only the Held_Out_Set's SHA-256 tree hash and its counts, never a case or a path.
- [ ] AC-32: THE Doctor SHALL fail when a file of the Replay_Fixture_Set or a Replay_Record holds an absolute user path, a `$HOME` path or a hit of `scripts/check-generic.py`.
- [ ] AC-33: WHEN the Replay_Harness runs for an engine and model, THE Replay_Harness SHALL run the whole set three times, give each case to the reviewer as the block `panel_digest.py --panel-request` prints plus its source excerpts, read the verdict with `receipt_ledger.parse_panel`, count an unparseable, failed or timed-out answer as a miss on a NEEDS-WORK case and as a false alarm on a PASS case, and write a Replay_Record with each run's catch rate (NEEDS-WORK cases answered NEEDS-WORK over all NEEDS-WORK cases) and false-alarm rate (PASS cases not answered PASS over all PASS cases), the worst of each across the three runs, the counts, the engine, the model, the CLI version, the git tree hash of the Replay_Fixture_Set and the date.
- [ ] AC-34: THE Replay_Harness SHALL run the baseline on Fable, fall back to Opus only when the Fable call is refused for quota or credits, and record in the baseline Replay_Record which model ran and why.
- [ ] AC-35: THE Reviewer_Registry SHALL mark an engine and model `allowed` only when its Replay_Record names the baseline model it was compared against, carries the same fixture tree hash as that baseline record, has a worst catch rate of at least the baseline's worst catch rate minus 0.05, and has a worst false-alarm rate of at most the baseline's worst false-alarm rate plus 0.10.
- [ ] AC-36: THE Doctor SHALL recompute every `allowed` entry of the Reviewer_Registry from its Replay_Record and the current baseline Replay_Record, and fail when the AC-35 bound does not hold, when either record's fixture tree hash differs from the tracked Replay_Fixture_Set, or when the baseline model the entry names differs from the current baseline record's model, so a qualification against an Opus baseline never carries over to a Fable baseline.
- [ ] AC-37: THE Arming_Gate SHALL treat both External_Review_Reflex scripts, `registry/reviewers.yaml`, `registry/replay/` and the Reviewer_Pins as live arming files, the Reviewer_Pins path `company/config/reviewer-pins.json` being a new entry because the gate holds no `company/` path today, with a violation fixture writing the live copy and a benign fixture writing a worktree copy, or, for the gitignored Reviewer_Pins, the same relative path under the temporary HOME that `gate_selftest.py` provides.

## Non-Functional Requirements

- No guarantee from v7 to v11 is weakened on Claude Code: every existing gate keeps its fixtures and its decisions.
- No census, fixture or test reads client data; tracked census records and fixtures carry no arm name and no `$HOME` path, and guard fixtures use synthetic arm roots under the temporary HOME that `gate_selftest.py` already isolates.
- No secret, API key or message body is written to any tracked file.
- Every number in a commit or doc carries its measurement mode and source.

## Release Criterion

The minor release ships when every criterion has a CONVERGED verdict, and only after v11.0.0 is cut, so the version bump lands on v11.1.0. It becomes a major release (v12, cut with the `Octorato-Major:` trailer) only if the `plugin` kind or the census changes the schema of `packages.lock.json` or the block contract of an existing gate; an additive change stays minor (`docs/wiki/Self-Growth.md`). If the Runtime_Census marks both new harnesses as `gap`, the release ships the registry, the census and the whole tracing track, with both gaps documented, and adds no harness.

## Out of Scope

- LangChain and LangGraph as a dependency of the brain. Model choice belongs to the harness, and the 7 scripts above use vendor-specific features a model abstraction does not cover. A durable workflow engine is a different product; an arm that needs one adopts it on its own.
- LangSmith Deployment and any self-hosted LangSmith.
- The OpenTelemetry route to LangSmith. LangSmith documents only OTLP traces, and Claude Code's trace export is beta; revisit when both are stable.
- Hosted tools in Codex CLI, which its `PreToolUse` does not cover.
- The v11 work merged in #417 (no reply unreviewed); this spec builds on it and does not change it.
- Phase 4: an external engine forming a quorum alone, satisfying the Send_Gate, replacing the judgment-tier reviewer, or acting as a QA reviewer that qa-merge-gate honours without a harness QA subagent.
- Phase 4: verifying the served model with the vendor, or hashing a CLI's interpreter, modules and config directory; the receipt states what it covers (FR-05) and the plan names the rest as residuals.
- Phase 4: any runtime status change for Codex CLI or Gemini CLI; FR-01 and AC-03 stay the only route to `supported`.
- Phase 4: replaying real panel bodies; the ledger stores digests, and the bodies live in private transcripts, so the tracked replay set is synthetic.
